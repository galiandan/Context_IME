# 0.1.4 稳定性与性能修复

本版本仅生成本地 VSIX，不自动发布 Marketplace，不改变当前系统输入法。

## 修复与验证

- 控制器仅在有效事务完成后记录区域所有权。编辑/同区域移动使旧请求失效时，保留最新意图，等待旧进程退出后再执行。成功区域的普通编辑仍保留手动覆盖；失焦/禁用/切编辑器继续取消待执行工作。已经发出的系统操作仍不能保证撤销。
- 新增 Fake Adapter 回归先在旧实现复现两项失败，再修复：同区域编辑取消旧查询、同区域移动刷新快照；另验证有效请求重复事件仅执行一次。未使用真实输入法验证此竞态。
- `.gitattributes` 固定 LF，保持 vendored grammar 的原始校验和；没有关闭或放宽资源校验。
- 语义测试不受机器速度影响；生产单行与插入探测仍使用 5ms 预算，100ms 请求预算。独立测试验证超时降级和可信前缀。
- 普通单行编辑不再遍历并重建全部行缓存；分类结果内存记账修正。缓存超限保留可信前缀，尚未实现远处 token 淘汰和稀疏检查点，因此超出容量的后缀仍 unknown。
- 状态栏保留点击启停，悬停提供配置/诊断链接；诊断包含上下文与暂停原因（多光标、选区、未知语言、文件过大、预算超限、keep）。

## 本机验证

Linux x64，AMD Ryzen 7 9700X，Node 26.10.0，2026-09-27。

- `npm run check`：lint、strict typecheck、145 项测试通过。
- `npm run build` 与 `npm run test:integration`：独立 VS Code 用户目录运行通过；包含真实编辑器换行事件和暂停原因断言，未配置输入方案、设置次数 0。
- `npm run bench`：生产默认预算，修改前后同机运行。10,000 行连续单行输入 p50 从 0.334ms 降至 0.0156ms，p95 从 0.934ms 降至 0.0176ms；该场景 unknown=0。这是本次合成样例实测，不是所有工程的性能保证。
- 10,000 行冷缓存 p50 66.99ms、p95 87.16ms，暖查询 p95 0.00079ms。40,000 行末尾仍触发容量限制，快速 unknown 不能当成成功分类性能。
- Fcitx5 只读探测/查询 32 次真实进程，31 次 get、0 次 set，查询 p95 1.51ms。
- 原始 benchmark 报告保存至 `docs/benchmarks/0.1.4/`。额外冷启动/空闲报告及 CI 结果在完成后补记。
- 新增一次有上限的冷分词重试：先让出事件循环，重验 generation/版本/焦点与剩余 100ms 请求预算，最多再尝试一个 5ms 时间片；插入边界探测共享该次重试配额。独立进程 30 次实测 unknown 从 6 次降为 0 次，p50 26.59ms、p95 39.41ms。慢机器仍可能 unknown，单个正则也不能硬抢占。

## CI 与真实环境边界

首轮 CI 的五项失败已定位：Windows 的 CRLF 转换使 grammar 校验不一致，Linux/macOS 的部分语义测试触发冷分词超时。修复后将再次运行同一平台矩阵，结果待补记。

本轮不主动切换用户输入法。用户此前反馈 Linux 字符串、C++ 头文件场景正常，仅作为旧版本用户反馈；0.1.4 候选词、控件焦点、Windows/macOS 实际桌面均未验证。公开 API 仍不能完整观察 composition 与所有输入控件焦点。

第二轮 CI 已通过 Linux、Windows x64、macOS 两架构；Windows ARM64 暴露已有工具链配置错误：在 x64 runner 上选择了原生 ARM64 编译器。按 [msvc-dev-cmd 上游说明](https://github.com/ilammy/msvc-dev-cmd#inputs) 改为 amd64_arm64 交叉工具链。增加 VSIX 内 helper 的 PE/Mach-O 架构校验，防止包的平台标签与二进制不一致；ARM64 的通用 TS 测试仍运行在 x64 runner，不能表述为 ARM64 原生运行测试。
