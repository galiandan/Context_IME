# 07 · 轻量化设计与性能测量

## 1. 衡量原则

实测结果见 performance-results.md。下列保留初始限制与目标，不代表全部已达到。TextMate、Oniguruma WASM、grammar、缓存、子进程启动和真实输入法成本都必须纳入报告。

不宣传 CPU 永远为零、固定省电比例或“99% 不耗资源”。CPU 时间、唤醒和进程数量是资源指标，不等于电功耗；没有独立功耗测量就不作已验证省电结论。

## 2. 必须成立的结构约束

- 空闲且无未完成任务时没有周期定时器、分词或新增 helper 调用。
- 不扫描工作区、不监听整个文件系统、不每次取全文。
- 同一稳定上下文区域内移动/输入不查询或设置系统输入源。
- 至多一个执行中的设置事务、一个最新待执行目标。
- 无独立常驻子进程；系统原有输入法服务不算本扩展新增 daemon。
- 文档缓存、诊断、进程输出与分词工作有界，超限返回 unknown/keep。

## 3. 初始参数与限制

| 项目 | 初始值 | 性质与说明 |
| --- | --- | --- |
| 切换防抖 | 20ms，可设 0–100ms | 合并重复事件，不代表组合态检测 |
| 单批分词 | 128 行或约 4ms | 行与行之间让出，不能中途抢占同步正则 |
| 单行 tokenize timeLimit | 5ms | 协作式限制；stoppedEarly 结果不可信 |
| 单请求累计分词 | 100ms | 超限 unknown，保留可信检查点 |
| 单行长度 | 20000 UTF-16 单位 | 超限行与依赖其未知状态的后缀保持 |
| 默认文件阈值 | 2048KiB | 通过末尾 offset × 2 保守估算，不复制全文 |
| 文档缓存 | 最近 3 个、估算合计 8MiB | 非精确堆上限；状态、tokens、文本片段均计入 |
| 子命令/设置事务 | 1500ms / 2500ms | 硬停止等待边界，不是正常延迟承诺 |
| 进程输出 | stdout/stderr 各 64KiB | 超限终止并诊断 |
| debug 缓冲 | 256 条或 64KiB | 不记录代码或候选词 |

冷启动可能因 WASM 编译/grammar 加载超过热路径耗时，必须单列。单个正则长时间同步运行无法由 JS timer 抢占；若真实 grammar 的极端输入突破可接受预算，先提供最小复现，考虑 grammar 修复或有界 worker 隔离，不能声称现有 timeLimit 是严格 CPU 抢占。

## 4. 待校准性能目标

| 指标 | 初始目标 | 测量条件 |
| --- | --- | --- |
| 暖缓存分类 P95 | ≤ 1ms | 单光标，已加载 grammar，不含 OS 调用 |
| 常见单行增量更新 P95 | ≤ 5ms | 非病态短行，单独统计边界探测 |
| 热边界到源确认 P95 | ≤ 150ms | 包括默认防抖与短进程，分后端报告 |
| JS 常驻增量 | 记录后定预算 | 分 registry/WASM、grammar、文档缓存、UI |
| 单平台 VSIX | 实测后建立基线 | 本地 grammar/WASM/许可证不能为缩包省略 |

相比旧方案，不在没有加载真实 grammar/WASM 前承诺 8MiB 总堆或固定小包体。短 helper 也不先宣称一定优于常驻进程；以启动时间、CPU、峰值 RSS 和调用次数判断。

## 5. 可重复基准

固定硬件、OS、架构、VS Code/Node、依赖版本、grammar commit、输入法/桌面会话。记录电源模式和其他扩展；纯核心基准与真实 Extension Host/桌面测试分开。

fixtures 至少包含小文件、约一万行文件、接近大小阈值文件、超限文件、长单行、多行字符串与注释。每组测试：首次目标尾部查询、暖缓存连续移动、连续输入、前部修改跨行定界符、插删行/多处 edit、取消与重试、重复打开/关闭。

热路径至少 1000 次有效样本，冷启动至少 30 次；报告 p50/p95、样本数、unknown/失败数，不能只统计最快成功样本。报告分词行数、命中率、总 CPU 时间、后端 get/set 次数、真实进程启动次数；Fake Adapter 的调用次数不能当真实输入法延迟。

对照关闭插件、启用纯分类、启用真实后端三组。空闲观测 5 分钟，确认无新增调用和扩展周期活动。反复打开关闭 100 次，记录堆与 GC 后趋势；有界缓存不代表没有其他引用泄漏。WASM 内存与 native 峰值 RSS 单列，避免漏算。

## 6. 报告模板与回归

后续 `docs/performance-results.md` 必须列测试环境、提交/版本、实际命令、fixture、冷暖路径、p50/p95、分词量、调用量、内存趋势、失败/未知结果和限制。实际运行结果已记录，未运行的测量明确注明。

同机器可比基线的 p95 恶化 >20% 要调查；结构性要求如同区域重复 set、空闲轮询、缓存无界直接阻断。正常命令启动成为瓶颈后再评估原生模块/直连 D-Bus，并公开比较收益与新增依赖。
