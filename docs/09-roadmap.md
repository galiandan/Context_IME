# 09 · 实施顺序、决策与风险

## 1. 当前状态

本轮已实现本地预览版并执行 npm 检查、测试、基准、VS Code 集成及 VSIX 打包。目录起初仅有设计文档且不是 Git 仓库；保留了既有文件。实际结果与缺口见 delivery.md。

## 2. 分阶段执行

| 阶段 | 工作 | 可审查交付与退出条件 |
| --- | --- | --- |
| M0 核实与建基线 | 固定 npm/grammar 版本与许可，检查稳定 API 和参考源码 | 来源清单、关键 scope 样例、平台调用可行性限制 |
| M1 先写核心测试 | 分类、插值、边界、缓存映射、Fake Adapter 调度测试 | 关键验收失败用例明确，不以 Mock 证明系统切换 |
| M2 完成纯 TS 核心 | TextMate 装载、增量缓存、语言规则、策略/控制器 | 测试通过，分词量/超时/取消可测 |
| M3 当前平台完整流程 | 后端探测/设置/确认、配置向导、编辑器接入 | 能在当前条件验证的端到端报告；缺桌面则明确未验证 |
| M4 其余平台 | Windows/macOS 源码和构建、Fcitx5/IBus 真实适配 | 各后端非空实现、CI 构建，实机状态分别登记 |
| M5 体验与资源 | 状态栏、诊断、远程、焦点、性能基准 | 已知限制与资源数据，不虚报 composition 保护 |
| M6 交付检查 | lint/typecheck/test/build/bench/package，修复问题 | 平台 VSIX、实测报告、中文使用说明、第三方清单 |

保留原设计“先验证高风险能力”的优点，但不等待所有 OS 实机齐备才开始核心测试，也不把复杂语法推迟到不明确的后续阶段。首版五种语言的关键结构是交付要求。

## 3. 已确定的取舍

| 决策 | 原因 | 重新评估的证据 |
| --- | --- | --- |
| TextMate 单一分词基础 | 可复用 grammar，支持跨行/嵌套 scopes | 固定 grammar 的最小失败样例，局部修复不足 |
| 行级缓存与状态收敛 | 正确增量、减少重复工作 | 工作量/内存实测指出瓶颈 |
| 短时原生调用 | 无额外常驻进程，生命周期简单 | 测得启动成本超过可接受延迟/CPU |
| Linux CLI 首版 | 少依赖、可审查、易打包 | 可靠性/性能证据支持直连接口 |
| 注释默认 code | 符合最新需求，仍可配置 | 用户调整配置，无需改底层 |
| 弯引号无特殊规则 | 不混淆语言合法语法 | 将来另定义文本语言需求，不污染代码语法 |
| 三态策略与真实观测分离 | 避免声称未验证中文模式 | 不因显示简洁而合并状态 |
| 本地 UI 宿主 | 控制用户本机输入源 | 不用远程进程冒充本地能力 |

## 4. 风险台账

| 风险 | 措施 | 门槛 |
| --- | --- | --- |
| grammar 对未完成代码或插值 scope 不准确 | 固定版本、scope fixture、边界规则、局部探测 | 无可靠依据 unknown，关键需求不能用默认 code 掩盖 |
| 单个同步正则超预算 | 行长限制、timeLimit、极端输入基准 | 持续超时先复现，再修 grammar/考虑隔离 |
| 行映射或缓存收敛错误 | 多 edit 与随机编辑全量对照 | 前部定界符变化不得留下可信假后缀 |
| 短进程启动成本高 | 去重、冷暖分测、调用量统计 | 有数据后优化，不凭推测引入 daemon |
| Windows 目标/TSF 能力不足 | 目标线程确认、源和内部模式分开 | 不支持的模式明确声明，不模拟热键 |
| 焦点及 composition 信息有限 | 保守门控、前台校验、真实候选词测试 | 严重误切/丢字阻断正式自动支持 |
| Linux 全局状态影响其他应用 | 失焦清队列、框架/桌面矩阵 | 不能把 bestEffort 伪报窗口级保护 |
| 不可撤销旧请求 | 事务串行、进程退出确认、过期检查 | 忽略 Promise 结果不算修复 |
| 平台编译/签名/沙箱限制 | 平台构建与干净安装验证 | 不运行时下载替代、不擅自绕过系统保护 |
| 参考实现与发布包不一致 | 记录 commit、发布版本与许可 | 页面说明只作参考，不能当源码审计 |
