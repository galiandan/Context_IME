# 0.1.5 性能优化（2026-09-27）

已合入生产源码：区域起点扫描先过滤定界符，再检查嵌套 kind/path；分类结果 Map 按光标访问分配，编辑后释放。不增加轮询、持久 scope 索引或系统调用，保持 8MiB 保守估算上限和原有超时策略。没有安装或发布扩展，没有改变用户输入法。

## 同机对照

Linux x64 / Ryzen 7 9700X / Node 26.10.0。基线为 040d28e 的 0.1.4 cache/classifier，优化为当时的 0.1.5 生产源码；两者相同 esbuild CJS、Node --expose-gc、合成数据、默认预算。依次运行基线→优化，再优化→基线复测；每场景 1000 次，head-edit 为 100 次。内存取计时区间外 GC 后 heapUsed，包含完整测试进程，不是扩展独占值。原始 JSON 见 [数据目录](benchmarks/perf-0.1.5)。JSON environment.extension 读取执行时 package.json，仅是工作目录元数据，不能替代上述基线/优化代码身份。

一万行 Python 多行字符串输入 CPU 减少约 74%，p95 从 1.924ms 降至 0.481ms。逆序复测：基线 p95 1.871ms、CPU 1827.9ms；优化 p95 0.470ms、CPU 465.0ms。一万行完整缓存的场景在开始测量时，进程 heapUsed 比基线少约 1.8–1.9MiB；分类与 unknown 原因计数均一致。反复打开关闭 100 次后缓存估算归零。

小文件性能基本持平；不能把快速 unknown 当作成功分类的优势。token 较密的一万行和四万行文件仍受缓存容量限制。JS/TS/C++ 小文件的 unknown 为多字符定界符内部的保守判定。

## 验证与交付

- npm run check：lint、strict typecheck、150 项单元测试通过。新增长字符串/模板/注释区域身份与编辑后内存记账回归。
- npm run build、npm run test:integration：本地 VS Code 1.139.1 的独立用户目录通过，包含注释回车和 C++ include 回归；未配置输入方案，真实切换为零。
- npm run package:marketplace、npm run verify:vsix：Linux x64 本地包；grammar/WASM 校验与包身份检查通过。
- Windows/macOS 本轮未重新构建或实机测试；既有 0.1.4 CI 状态见兼容性文档。

本地文件：artifacts/vsix/vscode-auto-ime-0.1.5-linux-x64-Galiandan-CIO.vsix。Marketplace 未发布 0.1.5。

## 复现

```sh
npm run check
npm run bench:resources
npm run build
npm run test:integration
npm run package:marketplace
npm run verify:vsix
```

资源基准默认输出 artifacts/reports/perf-current；可用 AUTO_IME_PERF_DIR 指定独立目录。对照基线可用 node scripts/bench/prototype.mjs 构建（需 Git 提交 040d28e），优化使用当前源码构建，避免把历史隔离原型误当生产版本。

## 后续限制

起点扫描仍为线性回溯；按需 Map 降低实际分配，但保守估算不变，因此未解决大文件缓存容量。JS/TS/C++ 冷启动首次超时问题仍存在，本轮未修改预热/重试机制，也未重测五分钟空闲或真实 IME 切换。后续稀疏检查点与预热属于独立算法变更，需专门验证状态收敛、内存和取消行为。

后续 0.1.6 已实现 token 淘汰与初始化进展重试，见 [新报告](0.1.6-cache-cold.md)。
