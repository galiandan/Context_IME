# 0.1.1：注释回车后首字母仍使用 text

用户报告：Python `#` 注释使用 text，回车到下一行后，首字母仍进入输入法候选，随后切 code 导致候选上屏。

在本机 VS Code 1.139.1 的隔离 Extension Host 中复现：编辑器 type 换行先触发 document change，然后选区移到下一行第 0 列，但 selection.kind 为 undefined；输入字母时 kind 才为 Keyboard。0.1.0 只接受 Keyboard/Mouse，漏掉了换行事件。独立 TextMate 复现确认空白新行本身已能正确分类为 code。复现脚本 scripts/repro/newline-repro.ts 和 tests/extension.integration.ts；原始事件记录 artifacts/reports/newline-events.json 不含用户文档或输入文本。

修复不是接受所有未知来源事件：NewlineInteraction 只记住一次有效编辑器交互，并要求下一版本仅有一个在原光标处插入的换行（允许 CRLF、缩进），然后消费同一编辑器、版本和准确新位置的未知类型选区事件。失焦、编辑器变化、禁用和配置变化清除凭据；多处编辑、粘贴代码、撤销、API 移动和无先前交互均不匹配。公开 API 仍不能绝对区分恰好模拟同一事件序列的第三方扩展，因此保留焦点观测限制。

确认上下文使用 code 策略后立即提交串行事务，不额外等待 switchDelayMs。该设置仍适用于 text 方案。不是拦截 Enter/type，不重放键盘事件，不提前猜测下一行上下文：多行字符串仍走实际分类。系统调用仍是异步的，不能宣称与下一次物理按键完全原子化，也不能宣称支持 composition 观测。

回归包含：真实 VS Code 中按回车后、输入任何字母之前 lastContext 必须为 code；Fake 设置在不推进防抖 timer 的情况下已接到 code 意图；旧进程仍在运行时新请求必须等待退出；失焦、后台、版本错误、选区错误、撤销和未授权事件不触发。

集成测试没有配置系统源，set=0；真实候选词行为仍需要用户在其桌面上复测。本轮不主动修改用户输入法，不安装新版到用户已有扩展目录；提供 0.1.1 VSIX 供升级。
