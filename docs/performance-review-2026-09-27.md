# 2026-09-27 缓存路径代码审查

本记录对应 0.1.8 的缓存优化；Marketplace 的 0.1.7 构建不含这些修改。0.1.8 的五平台 CI 和 Marketplace 发布结果见[发布记录](0.1.8-release.md)。

## 发现与修复

旧实现用数组线性查找字符串/注释起点。编辑时又让每个锚点遍历整批编辑；多行编辑还让每个缓存行遍历全部编辑，并在每个锚点上重新复制、反转编辑数组。对于大量编辑，这让行映射和锚点映射随“缓存行数 × 编辑数”增长。

现在锚点按行索引。常见的单锚点行直接保存一个对象，同一行有多个锚点时才保存按列排序的小数组；查询使用行索引和二分查找。普通单行编辑只访问被编辑行的锚点。涉及换行的事件使用编辑行区间、行数变化前缀和端点索引：缓存行通过二分查找映射；锚点只处理所在行的端点编辑及之前的总行偏移。编辑列表不再为每个锚点单独复制。

锚点估算从每个 64 字节提高到 128 字节，以计入索引结构的开销。这仍是缓存记账估算，不是 JavaScript 堆硬上限。

分类热路径也用线性 `tokens.find()` 定位光标左右 token；改为按单调递增的 token 结束位置二分查找。分词结果和边界探测语义不变。

## 差分微基准

环境：AMD Ryzen 7 9700X；Linux x86_64，内核 7.2.7-zen1-1-zen；Node v26.10.0。基线源码为审查前的提交 `40c298c`，两边使用相同 Python grammar、同一 fixture 和相同缓存参数。计时只覆盖 `DocumentCache.edit()`，不含语法分析和 VS Code UI。旧、新实现均在独立缓存上预先查询 2,500 行，每行各有一个字符串起点。结果为毫秒：

| 场景 | 样本 | 基线 p50 / p95 | 当前 p50 / p95 |
|---|---:|---:|---:|
| 40 次单行编辑，改动行分散在 2,500 个锚点行中 | 40 | 0.0651 / 0.2585 | 0.00076 / 0.00159 |
| 一个批次修改 2,000 个不同行，无行数变化 | 8 | 13.227 / 15.605 | 0.402 / 0.819 |
| 一个批次含 2,000 个换行编辑范围 | 8 | 18.002 / 33.432 | 0.720 / 2.498 |

此微基准隔离了缓存映射成本，不代表所有 VS Code 编辑的时延。单行编辑 p50 约快 86 倍；两类批处理 p50 分别约快 33 倍和 25 倍。

对 17,000 UTF-16 单位、6,000 个已缓存 token 的 Python 行，在 1,000 个标识符内部位置查询（不触发边界重分词）：基线 p50/p95 为 0.0345 / 0.0535ms，总计 32.71ms；二分查找并跳过 code scope 路径分配后为 0.00048 / 0.00130ms，总计 0.82ms。该结果只表示已缓存 token 的查找成本；光标落在定界符边界时仍会运行当前行的 TextMate 探测。

单独 Node 进程的保留堆快照中，2,500 个锚点 fixture 从基线 17,759,960 字节变为 17,976,400 字节，增量 216,440 字节；对应的缓存记账从 4,010,560 字节变为 4,170,560 字节。进程堆包含 Node、WASM、grammar 和 fixture，不能视作扩展独占内存。

同机项目资源基准 `npm run bench:resources` 通过。Python 10k 代码前部编辑 p50/p95 为 5.569 / 5.757ms，多行字符串前部编辑为 1.015 / 1.239ms。10k 多行字符串连续移动 1,000 次 p50/p95 为 0.0038 / 0.0093ms；多行字符串正文连续输入 1,000 次为 0.0182 / 0.0262ms，累计扫描 11,063 行并命中区域链接 1,000 次。此前每次编辑失效所有链接时，同一正文输入路径曾扫描约 10,009,000 行；本次增量失效避免了这次全量回扫。40k Python code fixture 暖移动 p50/p95 为 0.0172 / 0.0238ms，unknown 为 0。100 次缓存打开/清理后缓存记账每次均回到 0；GC 后 heapUsed 在 17.97–18.06 MiB 间波动，未见持续线性增长。

冷启动基准 `npm run bench:resources:cold` 每种语言各 30 次，包含新 Node 进程内 WASM/grammar 加载和 100 行 query，但不含 Node 启动。p50/p95 与 unknown 次数：Python 38.53 / 43.64ms（0）；JavaScript 64.55 / 65.78ms（0）；TypeScript 64.79 / 65.81ms（0）；C 41.59 / 42.03ms（0）；C++ 86.48 / 90.73ms（0）。

环境为 AMD Ryzen 7 9700X，Linux x86_64，内核 7.2.7-zen1-1-zen，Node v26.10.0。以上均为合成核心基准，CPU/RSS 含 Node、WASM 和 grammar，不是 VS Code Extension Host 或输入法功耗测试；没有修改系统输入法。原始数据位于本机忽略目录 `artifacts/reports/perf-current/`，不纳入版本库。
